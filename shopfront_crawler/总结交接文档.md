## 一、系统目标和数据链路

```text
Shopfront
  -> shopfront_crawler（OAuth、拉取、历史同步、Webhook、本地镜像）
  -> POS staging / Odoo integration API
  -> skr.orithos.com.au Sell
```

第一阶段的 crawler 不直接连接 Orithos MySQL，也不绕过业务 API 写生产表。所有商品、库存和销售导入都必须经过 POS/Odoo 集成接口，并保留来源 ID 以保证幂等。

主要组件：

| 组件 | 文件 | 职责 |
| --- | --- | --- |
| FastAPI 入口 | `shopfront_crawler/app/main.py` | 健康检查、授权、同步、Webhook、只读 API |
| Shopfront 客户端 | `shopfront_crawler/app/shopfront.py` | OAuth、Token 刷新、Reports、GraphQL、限流重试 |
| 同步逻辑 | `shopfront_crawler/app/sync.py` | 快照、历史分片、补偿、幂等 upsert |
| 数据模型 | `shopfront_crawler/app/models.py` | Token、商品、库存、Sale、SaleItem、同步运行 |
| POS 调用 | `shopfront_crawler/app/pos.py` | staging/import API 调用和结果记录 |
| Odoo 调用 | `shopfront_crawler/app/odoo.py` | Odoo 集成状态及镜像调用 |

## 六、日常同步规则

每日任务使用门店本地时区 `Australia/Adelaide` 的 `02:00` 执行：

1. 重新同步最近 3 个营业日；
2. 覆盖销售修改、取消、退款和延迟上传；
3. upsert 汇总、Sale、SaleItem、商品和库存；
4. 生成 POS 导入队列；
5. 失败记录保留并由后续任务重试；
6. 记录数量、错误和导入结果。

Webhook 只负责缩短发现延迟，收到事件后由 crawler 主动拉取完整 Sale/Product。Webhook 请求必须快速返回 2xx，不能在请求线程中执行完整同步。

## 七、销售导入安全规则

只有以下条件全部满足才允许写入正式 POS 销售：

- 有稳定 Shopfront Sale ID；
- 有完整商品行和支付信息；
- 每个商品都能按条码优先、SKU 兜底匹配；
- 门店、company、outlet 映射已校验；
- 销售状态和退款/取消语义可识别；
- 相同外部 ID 不存在，或本次是幂等更新。

缺少 Sale ID、商品行或支付信息时，只保存 crawler 汇总并标记失败，不得用报表汇总伪造正式销售。取消和退款必须通过 Orithos 的可审计状态或退款模型处理，不能删除销售记录。

## 九、故障排查

### 状态长时间不变

先读取 `/api/sync/status`、`/api/sync/runs`，再看 Dokploy crawler 日志，重点确认 Shopfront 超时、429 限流、响应过大或容器重启。不要因为单个分片耗时较长就重复提交任务。

### Sell 有商品但销售行没有名称

确认历史任务已完成，再按“销售修复 → coverage → catalog snapshot”的顺序执行。检查 `source_product_id`、POS token 和门店映射。源端没有名称的记录应保留缺失状态。

### 图片、品牌或分类为空

检查 Shopfront 商品的 `raw_payload` 和权限。若源端字段为空，不在 POS 侧伪造数据；待 Shopfront 补齐后再运行快照。

### 接口 500 或授权状态丢失

先检查 `/healthz`、部署 SHA、数据库卷和启动迁移。不要 Fresh Volumes，不要清空 SQLite/PostgreSQL 数据库。

## 十一、后续开发建议

1. 历史同步结束后，将最新状态和覆盖数更新到本文件或新增带日期的 handoff，不覆盖旧证据。
2. 完成未匹配条码人工映射，再考虑正式销售导入。
3. 若要增加 `demo` 门店，只新增门店配置并让该门店管理员单独 OAuth 授权，不复用 `skr` token。
4. 若修改 `pos-api` 或 Odoo 集成，先通过 Java 21 构建门禁，再部署；crawler Python 改动也要记录实际运行 SHA。
5. 任何生产写入、取消历史任务、替换库存或重置数据卷，都应先记录影响范围和回滚方式。
