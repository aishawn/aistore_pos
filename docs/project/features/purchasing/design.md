# 采购与收货设计

更新日期：2026-11-09。负责人：待指定。

## 目标

Orithos 是采购单、收货和库存变更的唯一可写账本。Shopfront 采购数据作为带来源 ID 的只读历史镜像。旧 Odoo 数据只用于迁移对账和历史查询，不继续接受新采购或收货。

## 页面与接口

- `/purchases` 读取 Orithos `GET /api/orders`，由认证主体限定 vendor，门店用户再限定 outlet。
- 创建和编辑通过 Orithos `/orders/*` 页面和 `/api/orders` 接口完成；采购单收货必须逐行记录，不能以整个订单状态更新代替数量。
- `/api/shopfront/purchasing` 只代理固定 crawler 域名和经 host 映射确认的 `skr` 来源。请求体或查询参数不能改变租户、来源门店或上游主机。
- crawler 历史单据保留来源状态、来源 ID、明细和采集时间；来源采购单不得自动增加现存库存。

## 账务与库存约束

- Orithos 采购单和收货使用认证租户/门店，不接受客户端扩大 `vendorId` 或 `outletId`。
- 收货按采购单行写数量，禁止超过未收数量；重复 `Idempotency-Key` 只回放同一收货结果。
- 采购收货和库存变化在同一事务内产生逐行回执与库存流水，可按来源收货重放核对。
- 未知商品、箱规、税码、成本或数量不得自动补值；迁移异常必须阻止门店切换。

## 迁移顺序

先完成页面与读取脱钩，再验收采购创建、发送、部分/完整收货、重复请求、退供应商、库存对账及操作者审计。其后只读抽取 Odoo 未结采购、核对供应商/商品/数量/金额并逐店切换。验收前不删除 Odoo 原始数据或停用旧服务。
