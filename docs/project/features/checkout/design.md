# 收银账本迁移设计

更新日期：2026-11-09。负责人：POS owner 待指定。源码候选：`0474672b`；生产仍以部署运行时为准。

## 业务与数据流

认证主体提供 vendor/outlet/user。Sell 搜索和目录浏览在该 outlet 取商品、价格、客户；checkout 接收商品 ID、数量、支付意图及幂等键，后端重新校验商品、门店价目表、GST 税率和开启的 register 后，创建销售、支付和库存流水。购物车金额由服务端重算。Shopfront 属于外部渠道来源，后续通过稳定外部事件 ID 幂等导入，不混入收银 checkout。

```text
认证 POS -> outlet 商品/客户/价格 -> Orithos checkout -> 销售/支付/库存流水
                                         |-> 按幂等键回放
```

## 接口与边界

- `GET /api/sales`、`GET /api/sales/{id}` 和 `POST /api/sales/checkout` 是原生销售路径；Odoo-only filter 下不开放旧的任意销售 create/update/void 路径。
- vendor/outlet/user 只取自认证上下文。checkout 每行必须引用本门店在售商品，数量为正，须存在门店价格和明确税率；缺失时拒绝，不使用客户端金额或隐式 GST 默认值。
- 挂单列表、挂单商品行和商品快捷键读取遵守相同门店范围；挂单金额使用已校验的服务端价格。
- `Idempotency-Key` 由服务端按 vendor 加锁并保存响应。请求摘要绑定商品、数量、门店、支付意图，不绑定客户端价格字段，允许原请求重试回放而不重复付款或扣库存。
- 当前 checkout 支持已有支付/现金舍入规则，但退款、班次完整对账、供应商收货、GST 日结导出及正式外部 EFTPOS 收单仍需分别验收。

## 异常与兼容

无认证范围、未知/跨店商品、无价、缺税率、数量无效、客户或收银机跨店、关机 register 均拒绝。事务失败时销售、支付、库存变动和幂等响应不得部分提交。旧 Odoo 页面/BFF 暂留作当前运行路径，逐域替换后再移除；不得双写。

## 上线门禁

本地单元/后端回归不是业务准入。须在专用隔离租户验证含 GST 商品的 POS 销售、分笔支付/重试、库存仅扣一次、退款、现金和关班对账，再核对数据迁移和备份恢复。生产逐店切换需要授权人与切换记录。
