读图要点

库存 ≠ 商品数量
商品是 SKU 主数据；同一个商品可在多个库位产生多条库存记录，所以 11,024 与 10,846 不要求相等。
销售单 ≠ 销售明细
一张销售单通常包含多行商品，因此销售明细数量大于销售单数量。
付款记录可多于销售单
分开付款、混合支付或多次支付会产生多条付款记录；187,392 不能直接当作交易数。
同步数量存在小差异
销售单差 6、销售明细差 47，说明两端快照时间、过滤条件或增量边界可能不同，需要按业务主键对账。

数据边界与对账口径

crawler

抓取或外部同步侧的快照。可用于来源核对，但不应直接作为 POS 页面实时业务数据。

POS staging

导入/暂存/对账侧的数据集。付款记录当前统计为 187,392，crawler 侧尚未稳定统计。

当前业务页面

Products 读商品，Inventory 读商品 × 内部库位，Sell 读销售单/明细/付款，Purchases 读采购与供应商。

建议对账键

商品：SKU/条码；销售单：Odoo order ID / reference；销售明细：order ID + line ID；付款：payment ID + order ID；库存：product ID + location ID。

图中“crawler / POS staging”只表达同步边界，不表示两套系统都在当前 UI 中直接提供实时业务数据。
