## 1. 项目和线上入口

Orithos POS 面向澳洲酒类零售店。Odoo 是商品、库存、客户、采购、销售和 POS 班次的唯一业务数据源；Next.js 提供收银和管理界面；Spring Boot 提供认证、业务 API 和 AI 能力。Classic MySQL POS 保留在仓库中作历史参考，默认不作为线上写入数据源。不要让 Odoo 与 Classic MySQL 双写。

- POS：<https://app.orithos.com.au/>
- Odoo：<https://odoo.orithos.com.au/odoo/point-of-sale>
- Dokploy：项目 `aistore` → 环境 `production` → Compose 服务 `aistorepos`
- Compose 文件：仓库根目录 `docker-compose.yml`
- 本地环境变量：仓库根目录 `.env`（含密钥；禁止输出、提交或复制到交接记录）

### Odoo 会话自动恢复

- 代码路径：`pos-ui/app/api/odoo/session/route.ts`（Orithos 已登录时可用服务账号恢复 Cookie）。
- 生产 `GET /api/odoo/session` 返回 `autoRecoverConfigured: false`（匿名请求 `user: null`）。因此前端自动恢复当前未配置/未生效；Dokploy Environment 内容在 UI 中被遮蔽，不能仅凭当前屏幕断定后端变量状态。
- 本轮匿名生产接口检查：`GET /api/odoo/session` 返回自动恢复未配置且无用户会话。此前已记录登录态下 DELETE Cookie 后恢复失败；配置凭据并重新部署后须重新验证。
- 默认决策：可先用现有 Odoo 员工账号作服务账号以恢复可用性；后续再换成最小权限专用账号。密码只放 Dokploy Environment，禁止写入 Git / 本交接文档。
- `917eeba` 部署后，Integrations 卡片会显示 `autoRecoverConfigured` 是否为真。
