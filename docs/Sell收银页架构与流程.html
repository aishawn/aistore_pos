2. 四区布局 + 顶栏

CSS Grid：lg:grid-cols-[380px_minmax(0,1fr)] + 支付条跨两列。设计意图：支付在上、购物车在左、点货在右；店/班次控件在页眉右侧，与支付条分离。

  • More Actions：All products / Sales History / POS Help / Close Register

2a. 顶栏 chrome（店/班次 · 非本单）

渲染在 OdooRegisterPage 页眉右侧圆角 pill 内。职责是会话与店面上下文，不是当前购物车的支付动作。

控件图标 / UI行为handler
收银机绿/琥珀点 + <select aria-label="Register">切换 POS config；有车 → Park & switch 确认selectRegister
RefreshRefreshCw（busy 时 LoaderCircle）重拉 bootstrap/会话/支付方式。不是后台 sync 状态灯loadPos() · title「Refresh register data」
HistoryHistory打开 Sales History 弹层openSalesHistory()
HelpCircleHelp页内 POS help / recovery 对话框setHelpOpen(true)
关班DoorClosed（最右；易被误认成菜单）Close register；有车会警告requestCloseRegister()

本页顶栏没有 hamburger / drawer；应用侧栏由 AppShell 提供，与本 pill 无关。

2b. 两区职责与重复入口

支付条（A）vs 顶栏 chrome（D）— 不要合并

区改什么频率
A · 支付条当前购物车 / 支付 / 挂单 / 清车每单高频
D · 顶栏收银机会话 / 刷新 / 历史 / 帮助 / 关班低频、偏管理

两区之间无功能重复。合并会把结账动作与关班/换机放进同一扫视带，关班误触代价高。产品结论：保持分离。

页内真实重复（有意或可瘦身）

动作入口建议
History / Help / Close顶栏图标 ↔ More Actions 瓷砖保留顶栏；More Actions 可后续瘦身为仅缺省动作 backlog
Finalise支付条 ↔ 购物车底栏有意双入口，同一 canFinalise / handler
Case / Qty±支付条或工作区 ↔ 行内 pack chips / ±保留；支付条是快捷路径
ParkPark Sale 按钮 ↔ 换机时 Park & switch场景不同，非重复按钮

若要减噪，优先整理 More Actions 与顶栏的薄重复，而不是把支付条和 chrome 并排。

7. 本轮优化（已实施）

  • 刷卡 Step：顶栏保留短标题 + 开关 + 一行「只记账」；左栏改为短链「待确认终端」
  • Finalise：顶栏与左栏共用同一门控与 handler；等待态文案 Confirm terminal below，title 说明仅聚焦
  • 挂单：Resume 主按钮；Discard 改为文字链样式
  • Exact Cash：强化找零可见性与「改金额可找零」提示
  • Case Quantity：title 写明切换包装 Each→6→12→24
  • 组件：pos-ui/src/components/odoo-sell/ — PaymentBar、CartAside、CatalogWorkspace、ParkedList
