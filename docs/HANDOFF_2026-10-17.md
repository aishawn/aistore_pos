## 1. 当前目标

本项目正在根据 Shopfront 对比报告持续优化 Orithos，重点是：

- 页面必须展示真实状态，不能用静态示例数据冒充线上业务数据。
- 未接通的按钮、筛选器和写入动作必须移除、禁用或明确标注不可用。
- 列表页需要有加载骨架、错误重试、空状态和移动端布局。
- 每一批代码推送到 `main` 后，使用 Dokploy 部署，再用已认证浏览器截图做只读验收。
- 禁止在真实商店执行销售、退款、采购收货、库存调整、现金操作、关账、账户/角色修改等业务写入，除非用户明确授权。

## 7. 推荐验收命令

从仓库根目录读取 `.env` 中的 `INITIAL_ADMIN_PASSWORD`，通过 Playwright 登录。不要把密码打印到终端或写入文件。示例登录请求：

```js
await context.request.post("https://demo.orithos.com.au/api/auth/login", {
  data: { username: "admin", password },
  headers: { Origin: "https://demo.orithos.com.au" },
});
```

验收必须记录：页面标题、关键文案、旧控件是否消失、页面错误、横向溢出和截图路径。若登录返回 522、部署版本不匹配或缓存头仍为 `s-maxage=31536000`，应记录为阻塞，不得标记通过。

## 8. 安全和数据边界

- 不要提交 `.env`、数据库 dump、Odoo 密码或 session token。
- 不要执行 Fresh Volumes；这可能删除商店数据。
- 不要在 live store 做销售、退款、收货、库存、现金或账户写入测试。
- Odoo 自动恢复配置由 Dokploy 的 `ODOO_SERVICE_USERNAME` / `ODOO_SERVICE_PASSWORD` 提供，凭据只能保存在服务端环境变量。
- 部署配置和完整 smoke checklist 参见 [DEPLOYMENT.md](../DEPLOYMENT.md)。
