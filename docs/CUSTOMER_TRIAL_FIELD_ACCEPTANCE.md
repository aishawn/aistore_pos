# 客户试用现场验收表

目标环境：`https://demo.orithos.com.au`，当前 Odoo 数据库为共享 `aipos_uat`。所有试用写入必须使用唯一测试标记，并在结束后清理；记录 Odoo 单据 ID、POS receipt、金额、GST、库存前后值和应用报告值。

## 设备验收

在客户实际收银设备上使用一个指定测试商品和 1 次测试订单：

| 设备 | 操作 | 通过标准 | 证据 |
|---|---|---|---|
| 打印机 | 打印测试收据、断开 USB/网络后重试 | 正常打印；断开时 UI 明确显示不可用且不重复扣款 | 收据照片、浏览器日志、订单 ID |
| 钱箱 | 现金支付完成后触发钱箱，随后手动关闭 | 仅现金流程触发；卡支付不误触发；失败可见且不重复销售 | 现场视频、订单 ID |
| 扫码器 | 扫描已知条码、未知条码、连续两次扫描 | 商品搜索/数量行为正确；未知条码不创建隐式商品 | 扫码值、订单草稿截图 |
| EFTPOS | 模拟批准、拒绝、超时、取消和重复回调 | 只有明确批准才完成销售；拒绝/超时可重试且不重复扣款 | 终端流水号、订单 ID、回调日志 |

## 离线边界

1. 在线打开收银台并加入商品。
2. 断开网络，确认顶部状态为 `OFFLINE`，尝试结账。
3. 必须阻止完成销售并显示恢复提示；刷新或恢复网络后购物车行为符合产品说明。
4. 恢复网络后重新报价，确认没有离线期间产生的隐式订单或重复付款。

当前产品契约是“离线 POS 不支持”，因此离线测试通过的含义是安全阻止交易，不是离线销售成功。

## AI 现场验收

- 使用至少 10 张脱敏真实供应商发票和 10 张脱敏真实酒标，记录字段级准确率：供应商、发票号、日期、GST、总额、行描述、数量、单价、合计、品牌、品名、年份、品种。
- 每个样本记录响应时间、HTTP/API code、provider、token/费用（若 provider 提供）、失败原因和人工修正次数。
- 连续请求直到达到应用配额，确认请求在 provider 调用前被拒绝；记录 429/配额响应和无 Odoo 写入证据。
- 暂停或替换 provider，确认 UI 显示降级错误、保留重试入口，不触发业务写入。
- 结构化 CTA 只能导航到允许的内部页面，不能隐式创建、改价、收货或付款。

## 业务闭环与回滚

- 销售：现金、刷卡、GST、找零、收据、库存和日报一致。
- 退款：原单关联、退款金额、库存、税额和现金差异一致。
- 关班：正确现金、错误现金、差异阻止/审批策略和重试均有记录。
- 采购/库存：部分收货、超量收货、重复提交、失败恢复、盘点并发冲突均有 Odoo 回读。
- 试用结束：按测试标记清理数据；若无法清理，保留记录并禁止转为客户生产数据。

正式放行前必须同时具备：设备证据、AI 样本报告、完整业务对账、备份恢复后的登录/POS 只读烟测，以及独立客户租户/数据库或书面接受共享 UAT 风险。
