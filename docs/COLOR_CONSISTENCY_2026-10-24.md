# POS 与品牌站配色统一（2026-10-24）

以本地 `/dashboard` 与 `/dashboard/workspace` 为参考，统一浅冷灰底、白色内容面、深灰文字和橙色品牌强调。参考页的插画、布局、多色模块保留；表格、收银、弹窗继续使用清晰的实色内容面。

本轮为本地源码与浏览器 fixture 验证，未构建、未部署、未验证线上版本。工作树已有大量其他改动，未将其打包提交或推送。截图反映共享工作区的实际状态，也包含其他会话并行更新的 Logo；本轮未编辑 Logo 源文件。

## 差异与处理

| 区域 | 原有差异 | 本次处理 |
| --- | --- | --- |
| POS 全局、导航、收银、库存、采购、客户、设置 | 旧高饱和橙、不同灰底、主按钮和选中态来源分散 | `--oh-*`、`--sf-*`、组件主题变量映射至共享配色；轻渐变用于工作区画布 |
| Dashboard / Workspace | 单独定义颜色，容易与其他页面漂移 | 基础文字、边框、橙色强调及七类模块色接入共享变量，保留插画和布局 |
| 报表 | KPI 卡片和类别图使用独立色值 | 改用共享模块色；图表继续保留多色区分 |
| 推荐与侍酒师 | 橙色选中边框搭配蓝底，悬停仍是旧蓝色 | 品牌交互改为橙色体系；蓝色信息提示保持独立语义 |
| 日期选择与行操作 | 选中/悬停蓝色、删除操作单独写死红色 | 日期交互改用品牌色，删除操作使用危险色变量 |
| AI | 助手发送按钮、侧栏选中态、文字存在独立色值 | 改用公共变量；保留既有 AI 球体资源 |
| 品牌站首页、功能、行业、AI、价格、关于、博客 | 原全局主色为蓝色 | CTA 改为深橙，标题强调、链接和示意界面使用品牌色；首页加入轻柔背景渐变 |
| 注册 | 按钮、步骤、选项、输入焦点独立写死蓝色 | 接入公共变量；预览使用现有可编辑 SVG 并同步颜色 |
| 品牌站首页平板布局 | 修改前 768px 的长指标文本会撑宽页面 | 调整该处字号与换行，未修改文案 |
| 既有深色主题 | 品牌主色、链接、状态前景和字体定义不一致 | 增加深色配色，区分白字深橙动作与浅橙深字组件控件；不新增切换入口 |

## 色值与维护规则

| 用途 | 浅色主题 |
| --- | --- |
| 品牌点缀 | `#f05a17` |
| 白字动作按钮 / 悬停 | `#c2410c` / `#9a3412` |
| 品牌浅底 | `#fff0e6` |
| 页面底 / 内容面 | `#f4f7fb` / `#ffffff` |
| 正文 / 次要文字 | `#20232b` / `#626b7a` |
| 边框 / 输入边框 | `#e3e7ee` / `#cbd3df` |
| 成功 / 错误 / 信息 / 警告 | `#117250` / `#b91c1c` / `#245be6` / `#92400e` |

- POS：`pos-ui/app/brand-tokens.css`；品牌站：`src/config/style/brand-tokens.css`。两个项目独立部署，分别保留一份内容完全相同的配色文件，浏览器验证脚本检查一致性。
- POS 正式入口仍是 `pos-ui/app/globals.css`；弃用的 `src/app/globals.css` 继续转引正式入口。
- 白字按钮使用 action 色；组件库控件使用 control/on-control 配对；小字号链接使用 link 色。深色主题避免用一种橙色同时承担白字按钮和深底文字。
- 模块辅助色、业务状态、商品自定义类别色保持各自含义。没有批量覆盖所有蓝色/橙色工具类，也没有重新着色照片或 Logo。
- 公共 API、数据类型、数据库、价格、GST、权限及支付请求逻辑没有改动。

## 验证结果

| 验证 | 结果与范围 |
| --- | --- |
| 配色浏览器验证 | 80 项：24 个页面/视口组合、48 组两主题语义色对比度、注册六步/选中/焦点/悬停/返回、7 个其他品牌站公开页；`/sign-in` 单列限制 |
| POS 路由布局 | 14 路由 × 390/768/1440px = 42/42；HTTP 200，无页面异常或横向溢出 |
| 当前收银交互 | 8/8：搜索与清除、列表/网格切换、现金不足拦截、找零、键盘焦点、模拟结账和收据三视口 |
| API 隔离 | 浏览器请求全部由 fixture 接收；真实业务写入 0。收银仅有 1 次 fixture checkout |
| 类型检查 | 两项目 TypeScript `--noEmit` 通过；未运行本地应用构建 |
| 定向 ESLint | POS 无错误，有 3 条既有 img 警告；品牌站有 4 个既有错误、2 个警告，已用修改前副本复现同样的 4 个错误 |
| 补充检查 | 新 runner 语法检查、两份配色文件一致、相对本次起始副本新增行无行尾空白 |

对比度检查覆盖共享正文、次要文字、链接、动作/组件按钮和七类模块文字，浅色及深色均至少 4.5:1；这不代表全站所有历史硬编码文字都已完成无障碍审计。

收银 fixture 为 HTTP 本地预览提供固定测试 UUID，因为该源没有 HTTPS 的 `crypto.randomUUID`。这仅验证模拟界面与请求控制，不证明真实支付、记账或生产安全上下文可用。

## 独立限制与额外发现

- 品牌站 `/sign-in` 本地返回 HTTP 500；无法确认该页实际渲染效果。它仍继承公共主题，本轮没有改认证或配置服务。
- 品牌站旧 lint 错误位于 `hero-ai-tabs.tsx`（effect 内同步 setState）和 `pricing.tsx`（3 处 any）；保留原逻辑，没有为配色任务改支付或状态逻辑。
- 额外尝试旧搜索竞态套件时，发现当前工作树在输入新查询后仍有 1 条旧结果，没有满足“立即清空”的断言。本次没有修改商品搜索逻辑；此项未被计入配色/普通搜索通过数，也不应将普通搜索 smoke 当成竞态回归通过。
- 旧收银套件仍依赖此前的分类入口、Due 文案及终端 checkbox。保留旧套件，新建当前界面专用的配色交互 smoke；不声称已通过旧套件的未知付款恢复/防重复完整验收。
- POS 历史页面中硬编码的浅色表面不属于全面深色重设计。本轮验证了两项目公共主题变量和品牌站注册页深色样式；未宣称 POS 全部历史页面深色视觉验收通过。
