# SKR 365 天扩展分群回测（2026-11-03）

## 范围与数据

本轮通过 Odoo JSON-RPC 只读获取数据，未写入 Odoo；两份评估产物的 `writeRequests` 均为空。

- 销售窗口：`2025-11-03` 至 `2026-11-02`，365 天。
- 交易：57,730 笔已完成 POS 订单、112,007 行。
- 销量序列：2,000 个有销量商品；评估对照集使用销量排序前 500 个。
- 有实际销售的日期：361 天；窗口内 5 个商品日为负销量（退款/更正）。当前评估器按 `max(0, units)` 处理，故这些负销量没有作为负需求建模。
- 历史库存：500 商品、365/365 个日期、182,500 条完整观测（2025-11-03 至 2026-11-02）；来源为 Odoo `qty_available(to_date)` 重建，不能等同原生逐日库存快照。
- 库存/销量一致性：107 个商品触发矛盾警告；这些商品不得用于库存服务水平或缺货标签验收。库存历史研究数据状态为 `READY_WITH_PRODUCT_EXCLUSIONS`，原生库存快照验收仍不足。

销售快照位于本机忽略目录 `.local/ai-eval/skr-sales-365-2026-11-03.json`，500 商品 sales-only 子集和历史库存位于同目录，分别为 `skr-sales-365-500-2026-11-03.json` 与 `skr-inventory-365-500-2026-11-03.json`。这些原始数据未提交，避免把完整门店交易和库存数据放进 Git。非个人数据的聚合回测 JSON 保存在 `docs/UAT_AI_365D_SEGMENTED_BACKTEST_2026-11-03.json`。

## 方法

脚本：`scripts/ai_forecast_segmented_eval.py`。扩展窗口 walk-forward，最小训练 120 天；每个 horizon 先以较早 70% folds 选择分群 champion，后 30% folds 作为 holdout。分群仅使用每个预测 origin 之前的销量，避免未来泄漏。比较当前模型目录中的各候选；准确率以加权 WAPE 计算。

探索性门槛：holdout WAPE 相对基线至少改善 5%、绝对 Bias 不超过 10%、预测安全违规为 0。该脚本是 sales-only 评估：不能证明缺货需求、库存策略或采购成本收益。

## 决策与下一步

- 不切换全店默认模型。暂时只把 TSB / Exponential Smoothing / Croston SBA 作为分群研究候选；再用第二个独立季节窗口复核。
- 先修复或隔离 107 个库存矛盾商品；确认退款符号和销售口径后，重新运行 net-demand 评估。
- 对库存策略结果只使用无矛盾商品，并与真实原生日快照交叉校准；`to_date` 重建库存不作为缺货真值。
- 成本、采购 lead time、促销/价格变化、到货延迟及实际缺货损失尚未与本轮样本逐商品逐日期关联，因此缺货率、过量库存、服务水平、规划成本均未验收；安全违规为 0 只表示预测分位数有限、非负且顺序正确。
- 数据只用于 SKR research/read-only 验证；无业务写入。
