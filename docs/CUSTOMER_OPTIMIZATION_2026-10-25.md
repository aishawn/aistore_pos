# 客户管理与定价优化 — 2026-10-25

本轮已完成本地实现与 fixture 验证，尚未发布，也未在真实 Odoo 验收。没有运行本地应用构建或 Maven，没有真实业务写入，没有修改 Java。保留了开始任务前和期间其他工作的未提交改动。

## 已实现

- 客户菜单收敛到客户档案、应收和按可用性显示的礼品卡；价格表归入 Stock。分组维护并入客户页弹窗，旧分组地址兼容跳转。Classic 收款、合并、对账入口跳至 Odoo 客户/应收页面。
- 客户快速创建仅展开姓名、手机和邮箱；高级信息保留企业、地址、分组和价格表。新增分组/价格表筛选、客户详情抽屉、可搜索分页选择器、保存失败保留输入和重复提交保护。
- 价格表详情集中展示全部类型的定价规则及适用客户，分别分页；规则编辑进入 Odoo。基础售价页面明确说明编辑商品 list price。
- 客户新建/编辑统一校验 customers.edit 和公司范围，验证关联价格表与分组；无应收权限的客户查询不返回 credit/total_invoiced。共享旧分组可读不可在本应用修改；已关联客户（含归档客户）的分组禁止删除。
- 应收按姓名、ID 稳定分页，取消 500 条截断和局部金额排序；非存储余额字段不支持搜索时分批扫描并在超时后返回可重试错误。未结发票分页，贷项以负数和原币种展示，提供 Odoo Accounting 入口。
- 礼品卡在 Odoo 查询域中先限定 gift_card 再分页，返回计划币种，按门店日期判断到期日。模块缺失、无计划、无卡、403 和故障分别处理。保持只读。
- 新增 Odoo 公开报价桥接方法 orithos_quote_prices，限制 POS 权限、配置/客户/商品/价格表公司与币种；内部调用 Odoo 定价引擎。优先客户价格表，再收银台价格表，无价格表才用商品基础售价。配置错误不回退基础售价。
- 报价与销售结账共用价格解析及报价签名逻辑，包装数量合并成基础单位计算阶梯价；返回逐行价格、来源、税额、总额。结账重新计算，变化则返回 QUOTE_CHANGED 并刷新报价，要求重新确认。退款保持原交易价格，销售与退款分别检查权限。
- 弹窗通过 portal 置于工作区之外，避免悬浮助手遮挡；保留焦点、Tab/Escape 和失败重试。分页按钮预留悬浮控件空间，筛选重置页码。
