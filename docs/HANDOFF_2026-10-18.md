## 构建故障专项交接

### 已知失败日志

Docker frontend builder 在 Next.js 静态生成 `/utilities/future-costs` 时失败：

```text
Error: Invalid revalidate value "function(){throw Error(... revalidate is on the client ...)}`
on "/utilities/future-costs", must be a non-negative number or false
```

失败点位于 Dockerfile 的 `npm run build`，不是 SQLite 实验性警告，也不是运行时 API 错误。Next.js 16 在客户端引用图中把同名客户端 `revalidate` 函数误解析为页面路由配置值。

### 当前源码处理

`pos-ui/app/utilities/future-costs/layout.tsx` 和 `pos-ui/app/utilities/future-prices/layout.tsx` 当前仅保留页面组件转发，不再导出路由级 `dynamic`、`fetchCache` 或 `revalidate` 配置；客户端页面在挂载后读取 API。

显式 `revalidate` 导出已移除；页面不在服务端预取数据，客户端挂载后通过 API 读取。当前源码中没有需要恢复的 `revalidate = 0` 配置。历史修复提交为 `496ed19`，当前 `main` 已包含该修复链路。

### 接手者必须核对

1. 在 Dokploy 控制台确认 frontend 构建使用的是当前 `main` 的最新提交，而不是包含旧 `revalidate` 导出的镜像/缓存。
2. 保存完整 frontend build log，确认 `/utilities/future-costs` 和 `/utilities/future-prices` 均完成静态生成/部署，不再出现 `Invalid revalidate value`。
3. 确认 frontend/backend 容器运行 SHA、部署时间和容器状态；公网 HTTP 200 或 webhook 200 不能替代这些证据。
4. 部署后只读复验两个动态路由：HTTP `200`、`Cache-Control: no-store`（或等价动态私有缓存策略）、Cloudflare 状态为 `DYNAMIC`。

本地按项目约束未运行 `npm run build`、`next build` 或 Docker build；已完成的静态检查只能证明源码和类型层面没有发现问题，不能替代 Dokploy 的真实构建日志。
