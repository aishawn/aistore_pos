# Orithos POS CLI

`tools/orithos-pos` is a thin Python client for `/api/pos/v1`. It stores only the API URL and token in `~/.orithos-pos.json` (override with `ORITHOS_POS_CONFIG`), and also accepts `ORITHOS_POS_API_URL` and `ORITHOS_POS_TOKEN`. Writes require `--confirm` and automatically send an idempotency key.

Read commands: `products|customers|suppliers|orders|sales|purchases|inventory list|get`. `sales quote --file quote.json` requests a current Odoo quote. `sales create --file sale.json --confirm`, `sales refund --file refund.json --confirm`, `inventory adjust --file adjustment.json --confirm`, and `purchases create --file purchase.json --confirm` submit one or more JSON/JSONL records; the equivalent generic command is `sync batch --resource sales|inventory|purchases --file records.json --confirm`. Every write accepts `--idempotency-key KEY`; by default the CLI creates a random key for that invocation. Reuse the same explicit key and identical file when retrying a command after an uncertain result. Server idempotency keys expire after 24 hours. Each accepted batch returns an operation ID; poll it with `operations get <id>`. Webhooks support `webhooks list`, `webhooks create --url URL --event operation.completed --confirm`, and `webhooks revoke <id> --confirm`. Purchase writes create draft orders only; receiving stock remains an explicit store workflow. Sale, inventory, and purchase writes are disabled by default in a fresh deployment and enabled only for the isolated `aipos_uat` environment after acceptance.

API documentation is served inside the POS at `/api-docs`; the OpenAPI asset is `/openapi.yaml`. No separate service needs to be deployed.
