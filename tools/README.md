# Orithos POS CLI

`tools/orithos-pos` is a thin Python client for `/api/pos/v1`. It stores only the API URL and token in `~/.orithos-pos.json` (override with `ORITHOS_POS_CONFIG`), and also accepts `ORITHOS_POS_API_URL` and `ORITHOS_POS_TOKEN`. Writes require `--confirm` and automatically send an idempotency key.

Read commands: `products|customers|suppliers|orders|sales|purchases|inventory|pricing|classifications|payment-methods|outlets|registers list|get`. Classifications are the shared Odoo product-category dictionary; pricing, payment methods, outlets and registers are constrained to the token vendor's Odoo company. `sales quote --file quote.json` requests a current Odoo quote. `sales create --file sale.json --confirm`, `sales refund --file refund.json --confirm`, `inventory adjust --file adjustment.json --confirm`, and `purchases create --file purchase.json --confirm` submit one or more JSON/JSONL records; the equivalent generic command is `sync batch --resource sales|inventory|purchases --file records.json --confirm`. Every purchase line must include numeric, non-negative `unitCost`, which maps to Odoo `price_unit`; missing costs are rejected. Every write accepts `--idempotency-key KEY`; by default the CLI creates a random key for that invocation. Reuse the same explicit key and identical file when retrying a command after an uncertain result. Server idempotency keys expire after 24 hours. Each accepted batch returns an operation ID; poll it with `operations get <id>`. Operation states include `queued`, `running`, `completed`, `completed_with_errors`, `failed`, and `unknown`; reconcile Odoo before retrying an `unknown` outcome. Webhooks support `webhooks list`, `webhooks create --url URL --event operation.completed --confirm`, and `webhooks revoke <id> --confirm`. Purchase writes create draft orders only; receiving stock remains an explicit store workflow. Sale, inventory, and purchase writes are disabled by default in a fresh deployment and enabled only for the isolated `aipos_uat` environment after acceptance.

API documentation is served inside the POS at `/api-docs`; the OpenAPI asset is `/openapi.yaml`. No separate service needs to be deployed.

## Orithos Hardware Connect (Windows register agent)

`tools/orithos-hardware-connect` is the Shopfront-style local agent (v1, tray icon) for receipt printers and cash-drawer kicks on `http://127.0.0.1:9170`, preferred over QZ Tray. On a register: `.\install.ps1` (publish + per-user logon task + tray), or `.\run-dev.ps1` with .NET 8 SDK, or `.\uninstall.ps1` to remove.
